# 風險追蹤清單

來源：`docs/technical-plan.md` §7（主要風險）與 §4（授權風險）。狀態依實際 repo 現況查證，非憑印象填寫（查證時間：2026-09-30，當時 `backend/`、`tests/`、`cv/` 目錄皆為空，尚無其他 agent 的程式碼落地)。

| 風險 | 影響 | 對策（來自技術規劃） | 狀態 |
|---|---|---|---|
| 訓練資料與手機側拍落差大 | 公開資料多為轉播或實驗室畫面，模型在真實使用情境（手機側拍）準確率可能大幅下降 | 編列標註人力與預算，建立自有資料集 | 尚未處理 |
| 標註成本 | 需標註擊球時間點、球位置、球場角點，人力成本高 | 先做半自動標註工具 | 尚未處理（截至查證時，repo 內無標註工具相關程式碼或設計文件） |
| 單鏡頭球速精度有限 | 只能得到估計值，精度不及雷達，過度宣稱會有產品/信任風險 | 定位為估計值；產品文案避免宣稱精確測速 | 尚未處理 |
| GPU 成本 | 球追蹤（TrackNet 等）需 GPU，批次處理成本隨影片量增加 | 批次排程、按影片長度計費 | 尚未處理（截至查證時，`backend/` 目錄為空，尚無排程或計費機制實作） |
| 現有開源網球專案成熟度不足 | 球場線偵測、球員偵測等開源範例多為研究原型，穩定性不足以直接上線 | 只當起點參考，不直接自行上線使用 | 尚未處理（屬持續性風險，非一次性可解決） |
| YOLOv8（AGPL-3.0）授權風險 | 若用於球員偵測，SaaS 商用可能被迫開源 Rally AI 自身程式碼，或需購買商業授權；卡住 M1 之後「真正」球員偵測開發 | 需法務確認；詳見決策記錄 `docs/decisions/0001-player-detection-license.md` | **已決定**（2026-09-30 使用者裁示：接受 AGPL-3.0，Rally AI 開源。後續待辦：repo LICENSE 檔案與 README 授權聲明尚未更新以反映此決定） |

## 備註
- 「尚未處理」狀態反映專案目前仍是全新 scaffold；查證時 `backend/`、`tests/`、`cv/` 目錄均為空，尚無其他 agent 提交程式碼，因此本表未發現任何風險已有「已落地」的具體緩解措施。
- 此表應隨專案進度更新；當 backend-engineer / cv-engineer / data-labeler 等角色的工作實際落地後（例如標註工具、GPU 排程/計費邏輯），product-manager 應重新查證並更新對應狀態，而非憑記憶假設已完成。
- 2026-09-30 更新：backend-engineer 已交付上傳品質門檻（`backend/upload_quality.py`）、cv-engineer 已交付 M1 姿態骨架疊圖（`cv/pose_overlay.py`），「GPU 成本」「開源專案成熟度」等風險目前仍未受這兩項工作影響（皆未使用 GPU 或球追蹤模型），狀態維持不變；下次有 GPU/球追蹤相關程式碼落地時需重新查證。
