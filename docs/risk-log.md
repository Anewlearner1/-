# 風險追蹤清單

來源：`docs/technical-plan.md` §7（主要風險）與 §4（授權風險），加上執行中發現的風險。狀態依實際 repo 現況與 `docs/real-footage-findings.md` 的實測記錄查證（最近一次查證：2026-10-07，HEAD `a04f21e`，126 個 Python 測試與 8 個 Node 測試通過）。專案整體進度見 `docs/status.md`。

| 風險 | 影響 | 對策 | 狀態（2026-10-07 查證） |
|---|---|---|---|
| 訓練資料與手機側拍落差大 | 公開資料多為轉播或實驗室畫面，真實情境準確率可能大幅下降 | 建立自有資料集 | **部分處理，但素材不對**。已有 3 支真實側面練習片、22 個使用者確認的擊球；另測過 4 支轉播精華片（姿態偵測率只有 31.8%、26 個候選全為誤報）。**沒有任何一支是 ≥60fps、腳架、底線後方的合規格素材**；Insta360 目標機位只有 5 張靜態截圖。 |
| **目標機位球員太小，全畫面姿態偵測失效（新增）** | 底線後方廣角畫面中球員約 80×200 px；全畫面 MediaPipe 在 5 張 Insta360 靜態圖中只找到 1 張（輕量/最精細版相同）。M1 在你的目標機位上無法運作 | 計畫 §3 的「偵測球員 → 裁切 → 姿態」 | **未處理**。人工指定裁切位置時 5/5（是上限，不是真偵測器的表現）。需要 cv-engineer 做偵測 + 裁切階段（ADR 0001 已放行 YOLOv8），並用一段 Insta360 原始影片驗證。 |
| 標註成本 | 需標註擊球時間點、球位置、球場角點 | 先做半自動標註工具 | **部分緩解**。`label_shots.py` 工具存在、燒入解碼器幀號；`eval_shot_timing.py` 評估腳本存在。已標註 3 支、22 個擊球，**僅使用者一位審查者**；球位置與球場角點無工具；標註人力與預算未確認。 |
| **標註可靠度（新增）** | 標註錯誤會直接污染所有準確度數字 | 以解碼器幀號、逐幀截圖標註；多位標註者 | **已踩到兩個坑，已修正做法**：(1) 使用者播放器的幀號比 OpenCV 解碼器多約 3 幀（Fed 1），曾造成「沒打到球」的誤判，並使「偵測器早 3 幀」的結論作廢；(2) 每 3 幀一張的截圖漏掉擊球瞬間，一度藏起 7 個 Fed 2 的擊球。Fed 2 仍有 10 個偵測只在每 3 幀截圖上被判為「沒擊球」。尚無第二位標註者可量測一致性。 |
| 擊球時間點只用姿態（原：只用手腕速度） | 非擊球的大幅手臂動作會造成誤報 | 球追蹤到位後與球軌跡融合 | **已量測**：22 個已確認擊球上，只靠姿態精確率 **0.52**、召回率 1.00。選用的球色過濾 + 合併 0.5 秒：**1.00 / 0.82**（Fed 2 單獨 0.91 / 0.77）。球軌跡反轉實驗沒有區別力，已棄用。仍待在目標機位與對打回合驗證。 |
| **球色過濾的脆弱性（新增）** | 只是「球色小點在手腕附近」：球拍/衣服/鞋若為黃綠色、光線或壓縮讓球消失、對打中球經過沒打的球員，都會出錯；小球（目標機位）可能完全抓不到 | 保持預設關閉；在目標機位上先測 | **未驗證於目標場景**。目前每支影片 4 個漏掉的擊球，都是色彩濾鏡沒找到球。合併窗口 0.5 秒是看過這三支影片才選的。 |
| 單鏡頭球速精度有限 | 只能得到估計值，過度宣稱會有信任風險 | 定位為估計值；文案保守 | **未處理**（M5 未開始）。API/設計以 null →「尚未分析」處理，沒有宣稱球速。 |
| GPU 成本 | 球追蹤需 GPU，成本隨影片量增加 | 批次排程、按影片長度計費 | **僅有設計層面**。無 worker、無 GPU 排程、無計費；`mlops/` 只有模型登記與草稿計畫；沙盒無 GPU，成本從未實測。 |
| 現有開源網球專案成熟度不足 | 球場線偵測、球員偵測等範例多為研究原型 | 只當起點參考 | **持續性風險**。球場四角檢查仍是 stub；球員選擇是「最大/最中央」stub。 |
| YOLOv8（AGPL-3.0）授權 | SaaS 商用可能被迫開源 | ADR 0001 | **已決定**（2026-09-30 使用者裁示接受 AGPL-3.0）。殘留：`cv/player_selection.py` 檔頭 docstring 仍寫「NOT YOLOv8/Ultralytics」，與 ADR 不一致，待 cv-engineer 更正。 |
| **LICENSE 仍是 placeholder** | 不是 AGPL-3.0 全文；公開發布時授權不具效力 | 逐字換成 gnu.org 全文 | **未處理，發布阻擋項**。需有人（你或法務）核對，不可憑記憶重建。 |
| **真實影片版權與隱私（新增）** | 轉播精華片有版權、所有影片含可辨識人物；repo 是公開 AGPL | `.gitignore` 擋 `videos/`、`data/` 與常見影片副檔名；截圖不進 repo | **已有基本防護**（已驗證目前沒有影片或截圖被追蹤，除官方 MediaPipe 測試照）。標註檔只含幀號。**資料集日後的隱私/同意處理仍需決定**。 |
| 機位穩定檢查為啟發式 | 通過閘門的影片仍可能是移動鏡頭；剪接也被當成晃動 | QA 建議累積位移/方向一致性 | **部分修復**：慢速平滑平移現在 FAIL；方向反轉的平移仍可漏過；轉播剪接被判 FAIL，**但訊息寫「手持」會誤導**（它分不出剪接與晃動）。門檻手選、未校準。 |
| 驗收門檻未定義 | M3/M4/M5 沒有數字；M2 也沒有 | PM 提案、使用者確認 | **未處理**。`docs/status.md` §5(d) 已列出 PM 提案（M2：精確率與召回率皆 ≥0.90、M3：≥0.85），待你確認。 |
| M4–M5 時程風險 | 球追蹤 + 球場校正 + 球速為最高技術風險，依賴 GPU 與真實資料 | 預留較多時間 | **未處理**。M4–M5 皆 not started；需在 M1–M3 以合規格素材驗證後才啟動。 |
