# ADR 0004: 不再進行 Insta360 目標機位測試

- 狀態：**已決定**（2026-10-07，使用者裁示：「不需要 360 的測試了」）
- 影響：`docs/status.md` 的 M1 狀態、下一步順序、5(b)；`docs/risk-log.md` 的「目標機位球員太小」。

## 決定

不再向使用者索取 Insta360 底線後方的原始影片，也不再把「在 Insta360 機位上驗證 M1」當作下一步或阻礙。

## 這代表什麼（PM 補充，避免日後誤以為這個問題消失了）

- **問題本身沒有被解決，只是不再追。** 已量測的事實：Insta360 靜態圖中球員約佔畫面高度 14%，全畫面 MediaPipe 在 5 張中只找到 1 張；同款機位下裁切後 5/5（人工指定裁切位置，是上限）。側面/斜後方素材中球員佔 20–46% 時，偵測率 99.5–100%（轉播精華片 31.8%，球員大小不是唯一原因）。
- **因此產品現在的合理範圍是：球員在畫面中夠大的拍攝方式**（目前量測支持的下限約為畫面高度的 20%，**這是兩個數據點的推論，不是量出來的門檻**）。球員更小的廣角機位**目前不支援**，也沒有「偵測球員 → 裁切」階段。
- ADR 0002 的驗收素材規格（≥60fps、腳架、底線後方、純回合）中的「底線後方」若要保留，需要球員夠大；否則要把規格改成使用者實際會拍的機位。這個規格調整**尚未決定**。
- 若日後又要支援小球員的廣角機位，需要補「球員偵測 + 裁切」（ADR 0001 已放行 YOLOv8），再用該機位的影片驗證。
