## 結論先講

**仍然沒有任何里程碑達到 done-against-criterion**，但跟 10 月 1 日不同的是：**現在有真實影片的實測證據了**，而且它改變了優先順序：

1. 只靠姿態的擊球偵測**幾乎不漏、但約一半是誤報**（22 個已確認擊球，42 個偵測，精確率 0.52、召回率 1.00）。
2. 加上「手腕附近有球色小點」的選用過濾後，**精確率升到 0.95，召回率降到 0.82**；沒看過的那支（Fed 2）是 0.91 / 0.77。樣本小、三支都是側面練習片，**不能代表你的目標機位**。
3. **球員很小的廣角機位（Insta360 截圖，約佔畫面高度 14%）上，目前的全畫面姿態偵測幾乎失效**（使用者 2026-10-07 決定不再測這個機位，見 ADR 0004；問題仍在，只是不追）**（5 張靜態圖只找到 1 張），M1 缺「偵測球員 → 裁切」這一階段。這是目前最大的技術阻礙。
4. 標註流程踩到兩個坑（播放器與解碼器幀號差約 3 幀；每 3 幀一張的截圖漏掉擊球瞬間），已修正做法。

## 3. 真實 vs. stub

|---|---|---|
| fps 檢查 | 真實 | 邊界測過。 |
| 機位穩定檢查 | 真實但是啟發式 | 分不出剪接與晃動；門檻未校準。 |
| 球場四角檢查 | **stub** | 恆回 `NOT_IMPLEMENTED`。 |
| 影片資料夾與掃描（`backend/library.py`） | 真實 | `ingest`/`scan`；可加 `--shots --ball-filter --merge-within-s`；已在使用者的 Windows 電腦上跑通。 |
| `POST /upload`、`GET /uploads/...` | 真實 | SQLite 持久化。 |
| 處理 worker（`backend/worker.py`） | 真實但最小 | 手動啟動（`python -m backend.worker`）；跑姿態 + 擊球偵測並寫入 `shots`，失敗存原因。**不做**正反拍標籤、球速、重試、GPU、排程、計費。已在一支真實影片上端到端跑通。 |

## 4. 全域缺口

1. **沒有符合規格的素材**：目前測過的 9 支真實影片都不是 ≥60fps 腳架機位。你的 Insta360 原始影片我們**還沒收到**（只有 5 張靜態截圖）。
2. **目標機位上 M1 失效**，偵測 + 裁切階段未做。
3. **無球追蹤、無 GPU**：M4、M5 卡在這裡；球色過濾只是粗略的「球在附近」訊號，不是追蹤。
4. **M2/M3 驗收門檻已定**（ADR 0002），M4/M5 仍無數字；目前沒有任何一支**合規格**素材可供驗收。
5. **標註只有一位審查者（你）**，沒有第二位獨立標註者可量測一致性。

## 5. 需要使用者決定（PM 建議，非已做的決定）

**(a) 發球 / 高壓球 — 已決定（2026-10-07）**：不納入 M3 統計，輸出 `other`/不適用（`docs/decisions/0002-*.md`）。

**(b) 符合規格的真實影片（Insta360 部分已於 2026-10-07 撤銷，ADR 0004）**：你已提供 9 支非規格素材與 5 張 Insta360 截圖，足以發現上述問題。**下一步最有價值的只有一件事：一段 Insta360 底線後方的原始影片（20–60 秒、盡量 60fps）**，它同時解鎖 M1 的偵測 + 裁切驗證與球色過濾在小球上能不能用。更大的資料集（PM 先前估 15–20 支）可以等這一步之後再說。

**(c) 專屬 repo**：仍待你在能建立時建一個，應排在任何公開發布與大量資料進來之前。

**(d) 驗收門檻 — 已決定（2026-10-07）**：M2 在 ≥10 支未用於調參的**合規格**素材上，一對一配對、容差 ±0.33 秒（ADR 0003，原 ±10 幀），精確率與召回率皆 ≥ 0.90；M3 在已定位的擊球上正反拍正確率 ≥ 0.85；M4/M5 在能量測前不定數字。細節與釐清見 `docs/decisions/0002-acceptance-criteria-and-serve-scope.md`。目前 3 支非合規格練習片**不計入驗收**。

**(e) 球色過濾要不要變成預設**：目前**不建議**。目標機位與對打回合都沒測過；等 Insta360 影片的結果再決定。

## 5.1 2026-10-07 團隊決策（ADR 0005 授權）

- **已完成**：使用者提供持拍手（API + 上傳畫面三選一，預設「不確定」）；雙手距離線索；合併策略選項（預設不變）；LICENSE 換成 AGPL-3.0 全文；球拍偵測實驗（MediaPipe EfficientDet，免費）。
- **決定停止在 46 拍上調規則**：近幾次改動只差 1–2 拍，屬雜訊。M3 下一步卡在**資料**，不是程式。
- **球拍偵測**：不提升正反拍判斷，但用來推測持拍手 6/7（舊方法 2/7）；需左手球員影片驗證後，才考慮在使用者選「不確定」時使用。
- **球場四角檢查暫緩**：現有素材（7 支影片、5 張 Insta360 截圖）沒有任何四角都入鏡的畫面，做了也無法驗證；維持 `NOT_IMPLEMENTED`，等驗收影片（規格已建議四角入鏡）。
- **沙盒限制**：PyTorch／Hugging Face／gnu.org 被代理擋住，所以 YOLOv8 無法在此安裝；改用 MediaPipe 物件偵測（Apache-2.0）。若之後一定要 YOLO，需在使用者自己的電腦或可連線環境執行（免費，不需付費）。
