# 台股 AI 投資團隊

**委託目標：3 年內把新台幣 100 萬變成 300 萬。**

先把數學攤開：

| 項目 | 數值 |
|---|---|
| 所需倍數 | 3.0x |
| 所需年化報酬 | **44.2%** |
| 所需月報酬（等速） | 約 3.1% |
| 對照：台股加權指數長期年化 | 約 8–9% |
| 對照：頂級主動基金長期年化 | 15–25% |

這個目標遠超台股大盤的歷史紀錄，屬於高難度但非天方夜譚的區間。團隊的設計原則：
**用集中、動能的方式追目標，但用程式碼強制執行的風控確保帳戶不會歸零。**
帳戶活著，才有機會；賠光了，目標就永遠不可能。

團隊預設操作**模擬帳戶**（paper trading），不連任何券商，但完整模擬台股的整股交易單位、
手續費/證交稅與漲跌停限制，讓績效數字盡量貼近真實。

### 團隊成員（每位都是一次 Claude 呼叫）

```
市場資料 ──┬── 宏觀策略師                    ┐
           ├── 基本面分析師                  │
           ├── 技術分析師                    │ 並行
           ├── 籌碼分析師（三大法人/融資融券）│
           └── 催化劑分析師（可用網路搜尋）    ┘
                     │
               多方研究員 ──► 空方研究員
                     │
               風險長（結構化裁決：核准/最大曝險/否決清單）
                     │
               投資組合經理（結構化決策：交易指令）
                     │
          程式風控引擎（硬性上限，LLM 無法覆寫）
                     │
               模擬帳戶成交 → 報告 → Discord
```

| 角色 | 職責 |
|---|---|
| 宏觀策略師 | Risk-on / Risk-off 判定、上市 vs 上櫃資金偏好、建議總曝險 |
| 基本面分析師 | 成長品質、估值、財報/法說風險，每檔 1–10 分 |
| 技術分析師 | 2–8 週波段型態、進場區、停損、目標位，含漲跌停警示，每檔 1–10 分 |
| 籌碼分析師 | 三大法人買賣超、融資融券餘額變化，判讀籌碼穩定度，每檔 1–10 分 |
| 催化劑分析師 | 法說會、月營收、除權息、宏觀事件、新聞情緒（可啟用 Anthropic 網路搜尋） |
| 多方研究員 | 整合報告，提出最積極的 3–5 檔配置 |
| 空方研究員 | 逐檔攻擊多方方案，特別檢查上櫃股流動性與漲跌停風險 |
| 風險長 | 有否決權：允許的最大曝險、否決標的、要求修正 |
| 投資組合經理 | 最終指令：目標權重、停損、信心，誠實評估目標進度 |

### 標的範圍（可用 `TW_WATCHLIST` 覆寫）

- **上市權值股 + 半導體/AI 供應鏈**：2330、2317、2454、2382、3231、3661、2308、3037、6669 等
- **上櫃（.TWO）中小型動能股**：5274、6488、3529、8069、6415 — 流動性較低，單一部位上限更嚴
- **題材輪動股**：航運（2603、2609）、航空（2618）、生技（6446）、傳產（1477）

### 台股特有的規則（程式強制實作，不是提示詞）

- **整股交易**：買賣以「張」（1 張 = 1,000 股）為單位，下單股數無條件捨去到整數張，不做零股
- **交易成本**：買進手續費 0.1425%；賣出手續費 0.1425% + 證交稅 0.3%（手續費低消 NT$20），
  成本會計入部位成本與已實現損益，不是事後估算
- **漲跌停 ±10%**：資料層以「日漲跌幅是否已達 ±10%」標記個股，風控引擎會拒絕在漲停時買進、
  跌停時賣出（含停損），並在報告中列出「停損失效」警示，讓停損延續到下一輪而不是假裝成交
- **三大法人 / 融資融券**：從 TWSE（上市）與 TPEX（上櫃，best-effort）官方 API 抓取外資/投信/自營商
  買賣超與融資融券餘額變化，交給籌碼分析師

### 程式強制的硬性風控

不管 LLM 說什麼，`tw_team/risk.py` 都會把指令壓回這些限制內（可用環境變數調整）：

- 單一部位 ≤ 25% 權益（上市）/ ≤ 15% 權益（上櫃）；總曝險 ≤ 100%（不使用融資槓桿）；最多 6 檔
- 保留 ≥ 5% 現金；每輪最多 6 筆交易；最小單 NT$20,000
- 每筆買單必有停損（預設 −12%，最寬 −25%）；每輪開始先掃停損自動出場（跌停鎖死者跳過）
- **回撤熔斷**：自峰值回撤 ≥ 25% 後只能減碼，不能加碼
- 風險長的限制只能比系統更嚴；風險長未核准時只執行減碼
- 只能交易觀察清單內的標的；漲停不執行買單、跌停不執行賣單

### 安裝與執行

```bash
pip install -r requirements.txt
cp .env.example .env            # 填入 ANTHROPIC_API_KEY（或 `ant auth login`）
export $(grep -v '^#' .env | xargs)

python run_tw_team.py --once --no-trade   # 先看團隊怎麼想，不動帳戶
python run_tw_team.py --once              # 一輪完整流程，寫入模擬帳戶
python run_tw_team.py --status            # 看持股與目標進度（不呼叫 LLM）
python run_tw_team.py --interval 240      # 每 4 小時一輪；MARKET_OPEN_ONLY=1 只在台股盤中（09:00–13:30）
python run_tw_team.py --reset             # 重新開一個模擬帳戶
```

輸出：
- `reports/tw/tw_team_<時間>.md` / `.json`，以及 `reports/tw/latest.md`
- `state/portfolio.json`：模擬帳戶（現金、持股、停損、交易紀錄、權益曲線）
- 設定 `DISCORD_WEBHOOK_URL` 會推送摘要到 Discord

### 成本

每輪 9 次 Claude 呼叫（預設 `claude-opus-5`）。五位分析師共用同一份市場資料，
資料放在系統提示的快取區塊，同一輪內後續呼叫大多命中快取。
催化劑分析師的網路搜尋另計費，可用 `TW_TEAM_WEB_SEARCH=0` 關閉。

### 已知限制

- 漲跌停偵測是根據 yfinance 調整後收盤價的日漲跌幅估算（±10% 附近的門檻），
  非交易所當日的精確漲跌停價，除權息日附近可能有誤差
- 上櫃（TPEX）籌碼資料的官方 API 格式不如上市穩定，抓取失敗時會顯示「籌碼資料缺失」
  而不是讓整輪分析失敗
- 模擬成交採當日收盤價，不模擬盤中滑價（漲跌停鎖死情境除外）

### 接真實券商

`tw_team/risk.py` 的 `plan_orders()` 回傳的 `PlannedFill` 清單就是要送出的委託單（已是整股股數）。
要接真倉，寫一個模組把這些 fill 送到券商 API，成交後再呼叫 `Portfolio.buy/sell` 同步帳本即可。
建議先跑至少一季模擬、確認風控行為符合預期再考慮。

### 測試

```bash
python -m pytest tests -q
```

測試不需要網路與 API 金鑰，涵蓋目標數學、模擬帳戶（含手續費/證交稅）、風控引擎（含整股捨入、
漲跌停阻擋、上櫃部位上限）、籌碼資料解析、資料封包與報告格式。

### 檔案結構

```
tw_team/
  config.py     目標、觀察清單（上市/上櫃/題材）、風控上限、交易成本、模型設定（皆可用環境變數覆寫）
  goal.py       目標數學：所需年化、等速路徑、落後/超前判定
  data.py       yfinance 資料 + 波段交易特徵（RS vs 加權指數、ATR、52 週高、MA50/200、漲跌停標記）
  chips.py      TWSE/TPEX 三大法人買賣超 + 融資融券餘額（best-effort）
  portfolio.py  模擬帳戶（JSON 持久化，含整股捨入與手續費/證交稅模型）
  risk.py       硬性風控引擎：目標權重 → 整股股數，套用所有上限（含漲跌停阻擋）
  schemas.py    PM 與風險長的結構化輸出 schema（Pydantic）
  llm.py        Anthropic SDK 包裝：串流文字、結構化輸出、快取、網路搜尋
  roles.py      九個角色的系統提示
  team.py       流程編排
  report.py     Markdown/JSON 報告 + Discord
run_tw_team.py  排程入口
analyzer.py     共用技術指標計算（RSI/MACD/布林通道/均線），tw_team/data.py 依賴此模組
notifier.py     共用 Discord 推送原語（_post/_split_message），tw_team/report.py 依賴此模組
tests/          離線單元測試
```
