# AI 股市分析 Agents

這個倉庫有兩個獨立的程式：

| 程式 | 市場 | 說明 |
|---|---|---|
| `main.py` | 台股 | 單一 Claude 呼叫的技術分析報告（每小時） |
| `run_us_team.py` | 美股 | **多角色 AI 投資團隊** + 模擬帳戶 + 硬性風控（本文件） |

---

## 美股 AI 投資團隊

**委託目標：3 年內把 $30,000 變成 $1,000,000。**

先把數學攤開：

| 項目 | 數值 |
|---|---|
| 所需倍數 | 33.3x |
| 所需年化報酬 | **221.8%** |
| 所需月報酬（等速） | 約 10.2% |
| 對照：S&P 500 長期年化 | 約 10% |
| 對照：史上最強對沖基金長期年化 | 30–40% |

這個目標遠超任何分散式策略的歷史紀錄，達成機率很低。團隊的設計原則因此是：
**用高集中、高動能的方式追目標，但用程式碼強制執行的風控確保帳戶不會歸零。**
帳戶活著，才有機會；賠光了，目標就永遠不可能。

團隊預設操作**模擬帳戶**（paper trading），不連任何券商。

### 團隊成員（每位都是一次 Claude 呼叫）

```
市場資料 ──┬── 宏觀策略師      ┐
           ├── 基本面分析師    │ 並行
           ├── 技術分析師      │
           └── 催化劑分析師（可用網路搜尋）┘
                     │
               多方研究員 ──► 空方研究員
                     │
               風險長（結構化裁決：核准/最大曝險/否決清單）
                     │
               投資組合經理（結構化決策：交易指令）
                     │
          程式風控引擎（硬性上限，LLM 無法覆寫）
                     │
               模擬帳戶成交 → 報告 → Discord
```

| 角色 | 職責 |
|---|---|
| 宏觀策略師 | Risk-on / Risk-off 判定、產業輪動、建議總曝險 |
| 基本面分析師 | 成長品質、估值、財報風險，每檔 1–10 分 |
| 技術分析師 | 2–8 週波段型態、進場區、停損、目標位，每檔 1–10 分 |
| 催化劑分析師 | 財報、宏觀事件、新聞情緒（可啟用 Anthropic 網路搜尋） |
| 多方研究員 | 整合報告，提出最積極的 3–5 檔配置 |
| 空方研究員 | 逐檔攻擊多方方案，給最壞情境與替代方案 |
| 風險長 | 有否決權：允許的最大曝險、否決標的、要求修正 |
| 投資組合經理 | 最終指令：目標權重、停損、信心，誠實評估目標進度 |

### 三情境估值模型（樂觀/中立/保守）

跟目標數學、風控引擎一樣，這是**程式算出來的，不是 LLM 猜的**（`us_team/valuation.py`）。
每輪跑之前，會用 yfinance 抓到的基本面自動算出每檔標的的一年期目標價：

- **有獲利的公司**：用本益比法。`EPS(TTM) × (1+成長率)^年期 × 出場本益比`
- **虧損/早期公司**：本益比不適用，改用市銷率法。`隱含營收(TTM) × (1+成長率)^年期 × 出場市銷率 ÷ 流通股數`
- 樂觀情境 = 基準成長率 **+15 個百分點**、出場倍數 **×1.3**
- 保守情境 = 基準成長率 **-15 個百分點**、出場倍數 **×0.6**（且成長率有 -30% 下限，不會因為基準已經是負成長而讓保守情境「變好看」）
- 三情境用機率加權（預設樂觀 25% / 中立 50% / 保守 25%）算出一個機率加權目標價與隱含報酬

這張表會放進每一輪的共用市場資料，**基本面分析師**與 **PM** 的角色指令都要求他們交叉參考：
機率加權隱含報酬為負卻還要買，PM 必須說明為什麼不同意這個機械式估值。
所有假設都能用環境變數調（見 `.env.example` 的 `VALUATION_*`）。

單獨查詢（不跑整個團隊、不呼叫 LLM）：

```bash
python run_us_team.py --valuate FCEL NVDA AAPL
```

### 程式強制的硬性風控

不管 LLM 說什麼，`us_team/risk.py` 都會把指令壓回這些限制內（可用環境變數調整）：

- 單一部位 ≤ 25% 權益；總曝險 ≤ 100%（不開槓桿）；最多 6 檔
- 保留 ≥ 5% 現金；每輪最多 6 筆交易；最小單 $200
- 每筆買單必有停損（預設 −12%，最寬 −25%）；每輪開始先掃停損自動出場
- **回撤熔斷**：自峰值回撤 ≥ 25% 後只能減碼，不能加碼
- 風險長的限制只能比系統更嚴；風險長未核准時只執行減碼
- 只能交易觀察清單內的標的

### 安裝與執行

```bash
pip install -r requirements.txt
cp .env.example .env            # 填入 ANTHROPIC_API_KEY（或 `ant auth login`）
export $(grep -v '^#' .env | xargs)

python run_us_team.py --once --no-trade   # 先看團隊怎麼想，不動帳戶
python run_us_team.py --once              # 一輪完整流程，寫入模擬帳戶
python run_us_team.py --status            # 看持股與目標進度（不呼叫 LLM）
python run_us_team.py --valuate FCEL NVDA # 查三情境估值（不呼叫 LLM）
python run_us_team.py --interval 240      # 每 4 小時一輪；MARKET_OPEN_ONLY=1 只在美股盤中
python run_us_team.py --reset             # 重新開一個模擬帳戶
```

輸出：
- `reports/us/us_team_<時間>.md` / `.json`，以及 `reports/us/latest.md`
- `state/portfolio.json`：模擬帳戶（現金、持股、停損、交易紀錄、權益曲線）
- 設定 `DISCORD_WEBHOOK_URL` 會推送摘要到 Discord

### 成本

每輪 8 次 Claude 呼叫（預設 `claude-opus-5`）。四位分析師共用同一份市場資料，
資料放在系統提示的快取區塊，同一輪內後續呼叫大多命中快取。
催化劑分析師的網路搜尋另計費，可用 `US_TEAM_WEB_SEARCH=0` 關閉。

### 接真實券商

`us_team/risk.py` 的 `plan_orders()` 回傳的 `PlannedFill` 清單就是要送出的委託單。
要接真倉，寫一個模組把這些 fill 送到券商 API，成交後再呼叫 `Portfolio.buy/sell` 同步帳本即可。
建議先跑至少一季模擬、確認風控行為符合預期再考慮。

### 測試

```bash
python -m pytest tests -q
```

測試不需要網路與 API 金鑰，涵蓋目標數學、模擬帳戶、風控引擎、資料封包與報告格式。

### 檔案結構

```
us_team/
  config.py     目標、觀察清單、風控上限、估值假設、模型設定（皆可用環境變數覆寫）
  goal.py       目標數學：所需年化、等速路徑、落後/超前判定
  data.py       yfinance 資料 + 波段交易特徵（RS vs SPY、ATR、52 週高、MA50/200）
  valuation.py  三情境估值模型（樂觀/中立/保守目標價，程式計算）
  portfolio.py  模擬帳戶（JSON 持久化）
  risk.py       硬性風控引擎：目標權重 → 股數，套用所有上限
  schemas.py    PM 與風險長的結構化輸出 schema（Pydantic）
  llm.py        Anthropic SDK 包裝：串流文字、結構化輸出、快取、網路搜尋
  roles.py      八個角色的系統提示
  team.py       流程編排
  report.py     Markdown/JSON 報告 + Discord
run_us_team.py  排程入口
tests/          離線單元測試
```
